# 手柄（游戏手柄）指南

游戏手柄可以操作两个独立的位置：主窗口和游戏内叠加层。两者都在
**设置 → 手柄** 中设置。

## 两个开关 {#the-two-switches}

| 设置 | 默认 | 涵盖内容 |
|---|---|---|
| **用手柄控制应用** | 开 | AW Next 主窗口：游戏库、游戏详情、设置和搜索。 |
| **使用手柄控制游戏内叠加层** | 关 | 游戏内叠加层，在你游玩时由后台跟踪器驱动。 |

应用导航只是普通的窗口输入，没有任何开销，所以默认开启。叠加层控制会在后台跟踪器中加载
原生手柄组件，所以需要主动开启。

## 快捷键一览 {#shortcuts-at-a-glance}

按钮名称使用 Xbox 的称呼；应用会按你选择的布局显示它们。

<img src="../assets/img/controller-map.svg" width="700" height="422" alt="带有默认快捷键的游戏手柄：LT 打开游戏状态，RT 启动游戏，LB 和 RB 切换设置标签页，方向键移动焦点，A 确认，B 取消，X 搜索，Y 和 Start 打开设置，另外还有三种叠加层组合键" loading="lazy">
</div>

| 快捷键 | 默认 | 位置 |
|---|---|---|
| 打开 / 关闭叠加层 | **Back + Start + LB** | 游戏中 |
| 切换叠加层导航 | **LB + X** | 叠加层已打开 |
| 移动和滚动叠加层 | **LB + RB**（按住） | 叠加层已打开 |
| 确认 | **A** | 应用 + 叠加层 |
| 返回 / 取消 | **B** | 应用 + 叠加层 |
| 聚焦搜索框 | **X** | 应用 + 叠加层 |
| 打开设置 / 叠加层选项 | **Y** | 应用 + 叠加层 |
| 打开设置 | **Start** | 应用 |
| 启动所选游戏 | **RT** | 应用，游戏库 |
| 打开所选游戏的游戏状态 | **LT** | 应用，游戏库 |
| 上一个 / 下一个设置标签页 | **LB** / **RB** | 应用，设置已打开 |
| 滚动页面 | **LB** / **RB** | 应用，设置已关闭 |

叠加层开关使用三个按钮，所以不会在游戏中途误触发。每个叠加层快捷键
都可配置，可以设置一到三个按钮。

在游戏库中，摇杆在磁贴之间移动，**A** 打开游戏，相当于单击。磁贴上绘制的
两个控件对应扳机键：**RT** 启动所选游戏，**LT** 打开
它的游戏状态面板。如果没有选中游戏库磁贴，两者都不会有任何动作。

## 选项 {#options}

- **手柄布局**：提示和按钮名称所用的称呼。**自动** 在能识别时跟随已连接的手柄；
  其他选项是 **Xbox**、**PlayStation** 和 **Switch**。
- **手柄后端**：**自动** 会选择最合适的可用输入后端，**XInput** 兼容性
  最好，**GameInput** 适合较新的 Windows 版本。
- **绑定**：每个快捷键一到三个按钮。快捷键可以共用一个按钮（默认就是这样：
  **LB + X** 和 **LB + RB** 都使用 LB），输入层会确保按住一个组合键时不会
  触发另一个。同一个绑定中重复的按钮只算一次。叠加层开关还接受
  **Guide** 键；两种叠加层模式则不接受，因为读取它们的浏览器游戏手柄 API
  不能可靠地报告该键。
- **打开时聚焦叠加层**：让叠加层获得键盘焦点，这会使许多
  失去焦点就暂停的游戏暂停。默认关闭。
- **用手柄打开时向游戏发送 Esc**：在叠加层打开之前，向获得焦点的游戏发送一次 Escape 按键，
  这样许多游戏会暂停或打开它们的菜单。它只在游戏运行期间由手柄
  触发的打开时执行，绝不会用于键盘热键。默认关闭。

## 应用窗口 {#app-window}

开启应用导航后，在主窗口中按下任何游戏手柄按钮都会显示焦点环。
方向键或左摇杆在控件之间移动，上述快捷键同样适用。有两个细节：

- **B** 先退出获得焦点的文本框，再执行返回或取消，所以无需鼠标
  就能离开搜索框。
- **LB** / **RB** 在设置打开时切换设置标签页，在设置关闭时滚动页面。

移动鼠标或按下键盘按键会把控制权交还给鼠标和键盘。

## 游戏内叠加层 {#in-game-overlay}

**Back + Start + LB** 在运行的游戏上方打开或关闭叠加层。接着 **LB + X** 切换
导航模式：方向键或左摇杆移动焦点环，**A** 确认，**B** 取消，**X**
聚焦搜索，**Y** 打开选项面板。按住 **LB + RB** 时，左摇杆移动叠加层，
右摇杆滚动列表。

导航启用期间，页眉中会显示一个小的 **UI** 徽章，提示栏显示你自己的
绑定和布局。叠加层的其余部分见[叠加层指南](overlay.md)。

> [!IMPORTANT]
> Windows 不允许第三方应用独占捕获手柄，所以叠加层打开时，游戏仍可能
> 收到按钮输入。要让游戏暂停，请启用 **打开时聚焦叠加层**
> （大多数游戏在失去焦点时会暂停）或 **用手柄打开时向游戏发送 Esc**。

## 支持的手柄 {#supported-pads}

支持 Xbox 手柄、PlayStation DualShock 4 / DualSense 和 Switch Pro 手柄。Xbox
手柄通过 XInput 工作；PlayStation 和 Switch 手柄通过原始 HID 读取，所以不需要
厂商驱动。

## 未检测到手柄时 {#when-a-controller-is-not-detected}

1. 确认已打开正确的开关：应用导航和叠加层控制是分开的。
2. 明确尝试 **XInput** 后端；在某些版本中，**自动** 可能会选择无法枚举到该手柄的
   GameInput。
3. 在 Windows 游戏控制器面板（`joy.cpl`）中检查手柄。如果 Windows 看不到它，AW Next
   也看不到。
4. 报告错误时，请在 `%APPDATA%\Achievement Watcher Next\cfg\options.ini` 的 `[controller]` 部分中添加
   `debugLogging = true` 并重启。之后后台跟踪器会记录
   按钮级别的诊断信息。界面中没有该开关，因为输出很冗长；之后请
   把它关掉。

## 在 Linux 上 {#on-linux}

在 Linux 上，AW Next 从内核的输入设备读取游戏手柄，上述快捷键的工作方式相同。
Steam Input 运行时，它只读取 Steam 的虚拟手柄，所以一次按键不会被重复计数。
Steam Deck 和 Decky 插件见 [Linux 与 Steam Deck](linux.md#steam-deck)。
