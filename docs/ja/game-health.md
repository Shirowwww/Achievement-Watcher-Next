# ゲームの状態

ゲームの動作がおかしいときは、まずそのゲームの **ゲームの状態** パネルを開いてください。AW Next がそのゲームを認識できているか、
実績を読み取れているか、解除を通知できているかが分かり、該当する修復だけが提案されます。

ゲームのタイルの右上にある **ツール** ボタン、またはゲームの右クリックメニューから開きます。パネルには 3 つのタブがあります：
**状態**、プレイ中に監視するプログラムを設定する **実行ファイル**、そしてゲームごとに専用のポップアップのプリセット、位置、
サウンド、サイズを設定できる **通知** です
([ゲームごとの動作](notifications.md#per-game-behavior)を参照)。

## 3 つの状態 {#the-three-states}

| 状態 | 意味 |
|---|---|
| **準備完了** | ゲームが検出され、実績データが利用でき、AW Next が解除を監視しています。 |
| **確認が必要** | ゲームは動作していますが、セットアップの一部が不完全です。確認項目がどの部分かを示します。 |
| **未追跡** | 欠かせないものが欠けているため、解除を記録できません：ゲームの場所が分からない、実績データがない、または解除を書き込むエミュレーターがない、のいずれかです。 |

状態の下の文が原因を示し、確認項目がどの部分に問題があるかを示し、修復ボタンがまさにその部分に対処します。

- **シンプル** モードは結果を平易な言葉で表します(*実績データが見つかりました*、*ゲームの起動時に検出されます*)。
  **詳細** では、正確な件数、監視中のプロセス、通知の経路が加わります。
- **技術的な詳細** は、どちらのモードでも下部にあり、生の値をすべて保持しています。バグ報告には **コピー** を押してください。
  長い値はホバーするとスクロールします。

コンソールエミュレーターのゲームには、Windows の実行ファイルやゲームファイルは求められません。

オフラインでは、設定にかかわらず何も記録しないゲームもあります。Halo: Campaign Evolved と The Crew
Motorfest は実績をパブリッシャーのサーバーが付与するため、クラック版では何も保存されません。
パネルは初回起動からそのことを表示します。

## 確認項目 {#the-checks}

| 確認項目 | 答える内容 | 典型的な対処 |
|---|---|---|
| **ゲームファイル** | インストールフォルダーはまだありますか? | **ゲームの場所を指定** |
| **実行ファイル** | プレイ中に監視すべきプログラムはどれですか? | **ゲームの場所を指定** |
| **ゲームの識別** | このゲームはどの AppID とプラットフォームに照合されましたか? シンプルモードでは表示されません。 | **ゲーム ID ファイルを修正** または **AppID を手動で設定** |
| **実績データ** | 実績リストはありますか? 完全ですか? | **実績データを書き直す** |
| **エミュレーター設定** | Steam エミュレーターを必要とするゲームにそれがあり、どれが対応していますか? Ubisoft のゲームでは、Uplay ローダーと、それが実績を一度でも要求したかどうかも対象です。 | **エミュレーターのファイルをインストール**、**サポート対象のエミュレーターに切り替え**、または **Ubisoft の実績サポートを修復** |
| **進捗** | 解除やセーブは見つかっていますか? | ゲームを起動して何かを解除する |
| **進捗カウンター** | 単純な解除ではなく統計値を追跡する CODEX/RUNE 形式のゲームで、AW Next は各実績の裏にある統計値を取得しましたか? それを使うゲームでのみ表示されます。 | **進捗カウンターを取得** |
| **ゲーム起動の検出** | バックグラウンドのトラッカーは、このゲームの起動に気付きますか? それ自体では解除を記録しません。それはエミュレーターの仕事です。 | **このゲームを監視する** |
| **通知** | このゲームの最後の通知はどの経路で配信され、その理由は? | **テスト通知を送信** |

## 修復 {#the-repairs}

パネルには、このゲームを直せる修復だけが表示されます。各修復は、何を変更するか、以前のファイルがどこに
残るかを示します。バックアップや確認なしに何かが書き換えられることはありません。

| 修復 | 内容 |
|---|---|
| **ゲームの場所を指定** | 監視する実行ファイルを選ぶピッカーを開きます。 |
| **ゲームフォルダーを開く** | インストールフォルダーをエクスプローラーで開きます。 |
| **実績データを書き直す** | 実績リスト、アイコン、エミュレーターの設定を書き込み、既存のファイルは先にバックアップにコピーします。 |
| **エミュレーターのファイルをインストール** | サポート対象のエミュレーターのビルドをゲームフォルダーにダウンロードし、置き換えるファイルは `.bak` として残します。 |
| **サポート対象のエミュレーターに切り替え** | 何も記録しなかった別のクラックで動いているゲーム向け：その上にサポート対象のエミュレーターをインストールし、そのクラックの設定を `.bak` に名前変更します。 |
| **エミュレーターの切り替えを元に戻す** | 上の 2 つのどちらかを実行した場所に表示されます。ゲーム自身のファイルを `.bak` のコピーから戻し、サポート対象のエミュレーターを取り除きます。 |
| **ゲーム ID ファイルを修正** | エミュレーターが 1 つのゲームを示し、AW Next が別のゲームに照合した場合に `steam_appid.txt` を書き直します。正しい AppID を尋ね(AW Next の照合結果を候補として示します)、以前のファイルを残します。 |
| **進捗カウンターを取得** | CODEX/RUNE 形式のゲームについて、各実績を動かす統計値を Steam に問い合わせます。ゲームフォルダーには何も書き込みません。 |
| **Ubisoft の実績サポートを修復** | 対応する Ubisoft のゲームで、ローダーの設定、スキーマ、セーブのリダイレクトを 1 つのトランザクションで書き直し、触れたすべてのファイルをバックアップします。[Uplay のセットアップ](uplay-r2.md)を参照してください。 |
| **オフラインで実績を有効にする** | ローダーのログから、サインアウト状態だと認識しているために実績を一度も要求していないと分かる Ubisoft のゲーム向け。ゲームの隣の INI にプレースホルダーのセッションキーを 1 つ追加します。もう一度押すと取り除かれます。[Uplay のセットアップ](uplay-r2.md#a-game-that-never-asks-for-an-achievement)を参照してください。 |
| **このゲームを監視する** | ゲームをバックグラウンドのトラッカーに追加し、プレイ時間とリアルタイムの解除が記録されるようにします。 |
| **進捗通知をオンに戻す** | ミュートしたゲームの進捗通知を再びオンにします。 |
| **テスト通知を送信** | このゲームの名前とアートワークで、実際に使われる経路を通して通知を送ります。 |

> [!IMPORTANT]
> 不一致は必ずしもエミュレーターのせいではありません：ディスク上の ID に合わせて意図的にセットアップされているなら、
> そのままにしてください。**AppID を手動で設定**(右クリック)なら、そのたびにファイルを修正する代わりに、フォルダー名の不一致を
> 恒久的に解決できます。[Goldberg / GBE のセットアップ](emulator-setup.md#set-appid-manually)を参照してください。

## よくある状態と対処 {#common-states-and-what-to-do}

| パネルの表示 | 通常の意味 |
|---|---|
| *実績リストが見つかりませんでした* | ゲームに実績がないか、そのソースがオフになっています。**設定 → ソース** を確認してください。 |
| *このゲームには Steam エミュレーターが必要ですが、設定されていません* | 右クリックメニューの **エミュレーター修正を適用…** を使います。[Goldberg / GBE のセットアップ](emulator-setup.md)を参照してください。 |
| *それを読み取るエミュレーターのファイルがありません* | **エミュレーターのファイルをインストール** で対応するランタイムが入ります。 |
| *実績リストがゲームの探すものと一致しません* | **実績データを書き直す**。リパックのアップデートでよく起こります。 |
| *実績の進捗がまだ見つかっていません* | セットアップ後にまだプレイしていないゲームでは正常です。起動して何かを解除してください。 |
| *AW Next はこのゲームの実行中に監視していません* | **このゲームを監視する** でトラッカーに追加されます。 |
| *最後の通知を送信できませんでした* | テスト通知を送信してから、[通知](notifications.md#if-a-test-or-unlock-does-not-appear)を参照してください。 |
| *Windows がゲーム中の最後の通知を隠しました* | ゲームが全画面だった、または応答不可がオンだったため、通知は直接通知センターに行きました。[優先度の高い通知](notifications.md#priority-windows-notifications)をオンにするか、自動またはゲーム内オーバーレイを使ってください。 |
| *動作中 - Windows の代替が有効* | 不具合ではありません。自動配信がこのゲームに Windows 通知を選びました。[自動の判断の仕方](notifications.md#how-automatic-decides)を参照してください。 |
| *ゲームが実績を一度も要求していません* | 空の Ubisoft セッションをサインアウト状態と解釈しています。**オフラインで実績を有効にする** でブロックが解けます。何もどこにも送信されません。その後、ゲームを一度起動してください。 |
| *オフラインの実績がオンです。ゲームを一度起動してください* | 設定は書き込まれましたが、まだ何も判定されていません。隣のボタンは **オフラインの実績を無効にする** になっています。 |
| *ALI213、OnlineFix、GBE Fork… で動作* | そのゲームを実際に読み取っているエミュレーターで、そのゲーム自身のファイルから名前が分かります。この方法で動いている Ubisoft のゲームには Uplay の修復は提案されません。Uplay のレイヤーは壊れているのではなく、使われていないためです。Valve の `steam_api64.dll` を残すリリースが対象です：`Steam\steamclient64.dll` から動作する RUNE のビルド、または名前を変えた独自の GBE Fork(`steam_api64.v38`)を読み込む VOICES38 のリリース。後者の上にエミュレーターをインストールしないでください。online-fix の Ubisoft ビルドは認識され、そこでの実績修復はオンラインプレイが止まる可能性があると警告します。 |
| *一部のアイコンだけがありません* | **実績データを書き直す** で不足しているアイコンをダウンロードします。 |
| *1 時間以上プレイしたのに実績が 1 つも記録されていません* | ゲームを動かしているクラックが、おそらく実績を一切報告しません。提案された場合は **サポート対象のエミュレーターに切り替え** を使い、そうでなければゲームが自分のフォルダーから起動していることを確認してください。 |
| *ゲーム ID ファイル*(このゲームへの Steam ショートカットがある場合) | Steam は非 Steam ショートカットを、隣に `steam_appid.txt` がない状態で起動するため、エミュレーターは別の ID でセーブします。**実績データを書き直す** がそこにファイルを書き込みます。 |
