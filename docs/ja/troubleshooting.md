# トラブルシューティング

## まずはここから {#start-here}

問題が**1 つのゲーム**に関するものなら、まずそのゲームの **[ゲームの状態](game-health.md)** パネルを開いてください。
AW Next がそのゲームを認識できているか、実績を読み取れているか、解除を通知できているかが分かり、
該当する修復だけが提案されます。1 つのゲームの問題の多くは、ここで解決します。

このページの残りは、アプリ全体に影響する問題向けです。**設定 → ヘルプ** には、*うまく動かないとき*(ゲームの状態とトラブルシューティング)の下に
最初の確認事項の短縮版があり、*現在の設定* の行にはテーマ、通知モード、コントローラー、オーバーレイのホットキー、
有効なソースの数が表示されます。不具合かどうか確信が持てない段階での質問は、
[Discord サーバー](https://discord.gg/DjTMrDsXTh)でどうぞ。バグ報告には、アプリのバージョン、Windows の
バージョン、関係するソース、正確な手順、関連するログを含めてください。

## Linux では {#on-linux}

Linux 版には、このページが扱わない問題があります。AppImage は FUSE 2 がないと起動しません
(Ubuntu 24.04 では `libfuse2t64`)。キーリングがパスワードを求めるのは、自動ログインのときだけです。
Wayland でのオーバーレイのショートカットは、デスクトップのキーボード設定で自分で割り当てるものです。それぞれの対処は
[Linux と Steam Deck](linux.md#install)にあります。このページの残りは Windows について説明しており、Linux では
ログは `~/.config/Achievement Watcher Next/logs` にあります。

## ログとローカルデータを開く {#open-logs-and-local-data}

<div align="center">
<picture><source srcset="../assets/shot/diagnostics-panel-800.webp 800w, ../assets/shot/diagnostics-panel.webp 940w" sizes="(max-width: 700px) 100vw, 720px"><img src="../screenshot/diagnostics-panel.png" width="720" height="529" alt="設定 - 詳細、診断"></picture><br>
<sub>アプリとランタイムのバージョン、およびログ、データ、アップデートの確認への素早いアクセス</sub>
</div>

**詳細** タブは詳細モードにしかありません。表示されない場合は、**設定** の上部にある **インターフェース** のコントロールを
シンプルから詳細に切り替えてください。元に戻しても何も失われません
([getting-started.md](getting-started.md#simple-and-advanced)を参照)。

**設定 → 詳細 → 診断** でログまたはデータのディレクトリが開きます。既定のログのパスは次のとおりです。

```text
%APPDATA%\Achievement Watcher Next\logs
```

特に役立つのは、たいてい `Achievement Watcher.log`、`renderer.log`、`parser.log`、および該当するソースの
Watchdog のログです。スキャン、UI、通知にまたがる不具合では、それらのいくつかが必要になるため、
ファイルを手でコピーするのではなく、同じカードの **ログをエクスポート (.zip)** を使ってください。
ログを書き込むプロセスは止まらないため、手動のコピーでは書きかけの行を拾ってしまうことがあります。
エクスポートはアプリの実行中でも動作し、アプリ、Electron、Node、Chrome のバージョンを記した `about.txt` を追加します。

このアーカイブは公開の issue 向けなので、コピーはマスクされます。すべてのパスに含まれる Windows のユーザー名は
`[username]` に、キー、トークン、パスワードは `[redacted]`、`[token]`、`[apikey]` になります。
ディスク上のログは変更されず、マスクできないファイルは除外されます。
マスクは既知の形式に対して働くので、投稿する前にファイルを読んで確認してください。たとえば、自分の名前が付いたゲームフォルダーは
そのまま残ります。

ログは追記されるだけで切り詰められないため、クラッシュの記録は次の起動後も残ります。各実行は
マーカーで始まり、そのあとにバグ報告に必要な内容を含む `[diag]` ブロックが続きます。バージョン、インストールとデータのパス、
アプリの起動方法、言語とテーマ、すべてのディスプレイのジオメトリです。

```text
===== session 2026-08-11T00:53:31.890Z pid=19276 =====
[diag] app: Achievement Watcher 3.10.0 (packaged)
[diag] runtime: electron 43.4.0 · chrome 150.0.7871.224 · node 24.18.1 · v8 15.0
[diag] display: 3056414223 1080x1920 @1x work=1080x1872 rotation=270
[diag] display: 3933707034 (primary) 2048x1152 @1.25x work=2048x1104 rotation=0
```

このブロックを issue に貼り付けてください。ウィンドウのサイズや配置の問題は、ほとんどの場合ディスプレイのスケーリング
またはマルチモニターが原因で、続く `[MainWindow]` の行には、ウィンドウが表示、移動、リサイズ、閉じられるたびに
その境界とディスプレイが記録されます。

各ログファイルは 2 MB を超えると `<name>.log.1` にローテーションされ、1 世代前のものが保持されます。

## ゲームが見つからない {#a-game-is-missing}

1. **設定 → ソース** を開いて、該当する連携が有効になっていることを確認します。
2. **設定 → フォルダー** を開いて **スマート検索** を実行し、フルスキャンには **設定を生成** を使います。
3. ゲームライブラリやセーブのルートが独自の場所にある場合は、手動で追加します。
4. **インストール済みのゲームのみ表示** をオフにして、ゲームが既知なのにインストール済みと見なされなくなっていないか
   確認します。
5. エミュレーターのセーブの場合は、ゲームを一度起動して、実行用のフォルダーを作成させます。

古いセーブの残りだけがあってゲームのファイルが消えている場合、インストール済みのみのフィルターが
そのエントリを隠します。

メタデータを取得できなかったゲームもリストに残ります。ゲームが存在するかどうかはディスク上の内容で決まり、
オンラインの検索は飾りつけにすぎません。エントリにはローカルで分かっている名前が表示され、
あとのスキャンで補完されます。

## 実績がロックされたままか 0% と表示される {#achievements-stay-locked-or-show-0}

実行時の解除ファイルがなければ、実績リストが完全でも 0% になります。

ゲームの **[ゲームの状態](game-health.md)** パネルを開いてください。足りない部分が示され、実績データの書き直し、
エミュレーターのファイルの復元、別のゲームを指している `steam_appid.txt` の修正など、
その修復が提案されます。手動で確認するには：

- 検出された AppID またはプラットフォームの ID が正しいゲームのものか確認する。
- カスタムのセーブパスがないか確認する。
- 一致しない `steam_settings` のスキーマは、レポートを確認したあとにだけ修復する。
- 別のPCでプレイした場合は、その Steam アカウントを接続する：ローカルに読み取るものがないゲームは、
  その後 Steam プロフィールから読み取られ、そのゲームの詳細は公開されている必要があります。結果は 6
  時間キャッシュされます([接続したアカウント](sources.md#connected-accounts)を参照)。

Steam エミュレーターのセーブは、同じゲームでも `%APPDATA%\GSE Saves` と
`%APPDATA%\Goldberg SteamEmu Saves` に分かれていることがあります。AW Next は解除が入っている方を読み取るので、
手動で直す必要はありません。

実績セットのないゲームには、0% ではなく進捗バーがなく(または **設定 → 外観 → ライブラリのタイル** でそのバーを戻した場合は
**実績なし**)、達成率の統計から除外されます。

**AW Next の再生ボタンからは動くが、Steam のショートカットからは動かない。** 非 Steam ゲームとして Steam に追加した
クラック版のゲームは、独自のゲーム ID で起動され、GBE Fork は `steam_appid.txt` より先にその ID を読むため、
解除はショートカットの番号で保存され、ゲームのカードには届きません。ショートカットの開始フォルダー(Start
In)に `steam_appid.txt` があると、Steam は本来の ID を渡します。実行ファイルの隣だけにあるものは読まれません。
ゲームの状態は、開始フォルダーにそれがないショートカットを指摘し、その修復でそこにファイルを書き込みます。

**シーンクラックで動いているが、何も記録されない。** 実績を報告しないクラックもあります。
1 時間プレイして何も記録されない場合、ゲームの状態がそのことを示し、そのクラックがゲームの
Steam ライブラリのファイルなら、その上にサポート対象のエミュレーターをインストールすることと、あとで元に戻すことを提案します。

**Halo: Campaign Evolved と The Crew Motorfest はオフラインでは何も記録しません。** 実績はパブリッシャーの
サーバーが付与するため、どんなクラックやエミュレーターでも記録できません。それらのゲームの状態パネルがそのことを示します。

ソースごとの手順は、[Goldberg と GBE Fork のセットアップ](emulator-setup.md#common-problems)または [Goldberg Uplay R2 のセットアップ](uplay-r2.md#achievements-remain-at-0)を参照してください。

## 違うゲームに照合された {#the-wrong-game-was-matched}

ゲームのフォルダー名が複数の Steam リリースに一致し、自動の照合が誤ったものを選んだ場合は、
右クリックして **AppID を手動で設定...** を選びます。入力した AppID は `steam_appid.txt` に書き込まれ、
そのインストールフォルダーについて記憶されるので、以降の修復でも使われます。同じメニューの **手動の
AppID を解除** で元に戻せます。ゲームの状態の **ゲーム ID ファイルを修正** も
AppID を尋ねます。詳細：[ゲームの AppID を手動で設定する](advanced.md#set-a-games-appid-by-hand)。

不一致は必ずしもエミュレーターのせいではありません。ディスク上の ID に合わせて意図的にセットアップされているなら、
そのままにしてください。

## 名前、説明、アートワークがない {#names-descriptions-or-artwork-are-missing}

- オンラインの状態で更新して、アプリがメタデータのソースを再試行できるようにします。
- ゲームのプラットフォームの識別を確認します。誤った Steam AppID は、もっともらしいが無関係な
  メタデータを返すことがあります。
- Goldberg/GBE では、有効なローカルのスキーマがあれば、不足しているテキストの一部をオフラインで補えます。
- 自動のソースが失敗するときは、ゲームのカバー操作で再試行するか、ローカルのアートワークを選びます。

Steam の AppID だけがタイトルになっているカードは、名前の検索が空で返ったのに、AppID だけから得られるアートワークは
取得できたことを意味します。次のスキャンで検索が成功すると、番号は置き換えられます。

DLC やアップデートの実績は、タイトルの下に所属するグループを表示します(たとえば「Hearts of
Stone」のタグ)。Steam 自身の実績セットから、それがないゲームでは SteamHunters から取得されます。

隠し実績の説明は、利用できるすべてのソースが省略している場合、隠れたままになります。

## ゲームのアップデートで実績が追加されたが表示されない {#a-game-update-added-achievements-that-arent-showing-up}

キャッシュされたスキーマは、Steam が新しい実績を通知しないため、3 日ごとに Steam に対して自分で再確認します。
すぐに取得するには **設定 → 詳細 → 実績リストを再確認** を使います。これは **実績データの自動更新** をオフにしていても
動作します。そのスイッチも 設定 → 詳細 にあり、止めるのは定期的な確認と空の説明の修復だけです。どちらの確認も
既存の実績や解除を取り除くことはありません。`steam_cache` を手動で管理している場合にだけオフにしてください。

## アップデートが同じファイルで止まる {#an-update-is-stuck-on-the-same-file}

ダウンロードしたアップデートのファイルは、実行をまたいで保持されます。同じファイルでダウンロードが失敗し続ける場合は、
**設定 → 詳細 → キャッシュを消去** を使って、もう一度アップデートを確認してください。再ダウンロードできるキャッシュだけが
削除され、設定、ゲームのデータ、ログは残ります。

アップデートは通常、インストーラーの変更された部分だけをダウンロードし、失敗すると自動的に完全な
インストーラーに切り替わります。

AW Next は新しいバージョンを Windows 通知とタイトルバーのチップで知らせ、どちらをクリックしても、スキップしたすべての
バージョンのリリースノートを一覧するアップデートウィンドウが開きます。お知らせは閉じるまで残り、ゲームのあとに
再び表示されます。ゲーム中には表示されません。その間、トレイアイコンには青い点が付きます。**設定 → 更新を確認** で
ウィンドウがすぐに開きます。

**アップデートが拒否された。** すべてのアップデートは、インストールの前にプロジェクトの固定された署名証明書に対して検証されます。
任意の署名でも、同時に公開された SHA-512 でもありません。両方とも同じリリースから来るためです。拒否された場合は、
ダウンロードしたファイルが改ざんされたか破損している可能性がほとんどです。
上記のようにキャッシュを消去し、
[公式のリリースページ](https://github.com/Shirowwww/Achievement-Watcher-Next/releases)からダウンロードし直してください。

## 通知が表示されない {#notifications-do-not-appear}

1. バックグラウンドのトラッカーが動作していることを確認します。
2. ゲームを開き、その **ゲームの状態** パネルの通知の行を読みます。そのゲームの最後の通知を配信した経路とその理由が
   示されます。
3. **設定 → 通知** の通常、レア、オーバーレイのテストを使います。
4. 配信モードと選択したプリセットを確認します。**自動** では、オーバーレイのポップアップが出ないのは意図された代替であることが
   多いです：[通知](notifications.md#how-automatic-decides)を参照してください。
5. AW Next に対する Windows の通知の権限を確認します。
6. プレイ中やフルスクリーンのときだけ問題が起きる場合は、**設定 → 通知** の **優先度の高い通知** をオンにして、
   Windows の権限の確認を承認します。
7. 排他的フルスクリーンの外でオーバーレイをテストします。
8. テストや解除が失敗した直後にログを確認します。

ライブラリは更新されるのに通知が出ないなら、問題は通知の経路にあります。ライブラリも変わらないなら、
まずソースやセーブのパスを診断してください。

## OBS ブラウザーソースが空のままになる {#the-obs-browser-source-stays-empty}

1. **設定 → 通知 → OBSブラウザソース** の **プレビュー** を押すか、
   `http://127.0.0.1:8082/obs/?test=1` を開きます。10 秒ごとにサンプルのカードが出るなら、ページとフィードは
   動作しており、問題は OBS のソースの設定にあります。
2. 空白のページすら出ない場合：AW Next のほかのコピー、または別のプログラムがポート
   8082. を使用しています。そのアドレスを提供するのは、最初に起動したコピーだけです。
3. 解除と解除の間は空白のページが普通です。`?test=1` を使うと描画を確認できます。
4. **設定 → 通知 → トランスポート** で **Websocket @localhost:8082** がオンになっていることを確認します。ソースは
   そのフィードを読み取ります。
5. カードはソースのサイズいっぱいに表示されます。ぼやけて見える場合は、ソースのピクセル数を増やし、
   シーンでは小さく配置してください。

詳しいセットアップは、[配信で解除を表示する(OBS)](notifications.md#show-unlocks-on-stream-obs)を参照してください。

## 再生ボタンからゲームが起動しない {#a-game-will-not-start-from-the-play-button}

マニフェストやランチャーが要求するため、管理者権限を必要とするゲームがあります。Windows は、AW Next が通常ゲームを
起動する方法ではそれらの起動を拒否し、`EACCES` を報告します。

その場合、AW Next は Windows シェル経由で再試行し、通常の UAC のプロンプトが表示されるので、確認するとゲームが
起動します。それも拒否された場合、AW Next は管理者として再試行することを提案します。昇格されるのはゲームだけです。
昇格した AW Next は、通常のアカウントでは書き換えられないファイルを作ってしまうためです。
UAC のプロンプトを閉じた場合は、エラーではなく判断として扱われます。

## プレイ時間が記録されない {#playtime-is-not-tracked}

AW Next は、設定されたゲームの実行ファイルとそのプロセスの存続期間を追跡します。ランチャー、ヘルパー、
または別名のバイナリが代わりに起動する場合：

- ゲームを右クリックして、その設定を開く。
- プレイ中も動作し続ける実行ファイルを選ぶ。
- ランチャーやクラッシュハンドラーのプロセスは避ける。
- 保存後にゲームを再起動する。

`javaw.exe` 経由で起動し、自身のランチャーを終了する Java のゲームは、その Java の
プロセスを通じて自動的に追跡されます。

すでに間違っている合計を修正するには、**実績とプレイ時間 → プレイ時間を編集…** を使います
([ゲームのプレイ時間の編集](advanced.md#editing-a-games-playtime)を参照)。

## PlayStation のトロフィーがインポートされない {#playstation-trophies-do-not-import}

- *PlayStation のセッションの有効期限が切れました*：**設定 → ソース** でアカウントを再接続してください。
- *PlayStation が速度を落とすよう求めています* または *PlayStation により一時停止されました*：Sony がリクエストの頻度を制限しています。
  数分後にもう一度インポートすると、止まったところから続きます。
- *このアカウントにはまだトロフィーリストがありません*：インポートするトロフィーリストがアカウントにありません。

## Nemirtingas の Epic ゲームが何も記録しない {#a-nemirtingas-epic-game-records-nothing}

ゲームフォルダーにエミュレーター(`EOSSDK` ライブラリと、その隣の
`nepice_settings\NemirtingasEpicEmu.json`)がある場合、ゲームの **ゲームの状態** タブに
**Epicエミュレーター** の行が表示されます。

- **SavePath は `"appdata"` でなければなりません。** エミュレーターは実績を
  `%APPDATA%\NemirtingasEpicEmu` に書き込み、AW Next はそこを読み取りますが、それはこの値のときだけです。ほかの値では
  ゲームフォルダーに保持されます。ほかの値に設定されていると、行が警告します。
- **ゲームによっては Epic の起動引数が必要です。** 一部の EOS ゲームは、ランチャーが `-epicapp=...` などを
  渡したときにだけエミュレーターにサインインし、実績を保存します。エミュレーターが何も保存していない間、
  行には **Epic の起動引数を追加** が表示され、設定の `AppId` から、それらをゲームの起動設定に書き込みます。
  それらを渡す `.bat` でも動作します。
- エミュレーターを入れるとゲームが起動時にクラッシュする場合は、そのオーバーレイのプラグインをオフにしてください
  (`"Plugins": { "Overlay": { "Enabled": false } }`)。オンの間は、行がそのことを知らせます。

## Ubisoft または Uplay R2 で誤った操作が使われる {#ubisoft-or-uplay-r2-uses-the-wrong-action}

Ubisoft のゲームには、Steam GBE の操作ではなく、Ubisoft のメタデータと Uplay R2 の修復が適用されるべきです。
新しくフォルダーをスキャンして、ソースのアイコンを確認してください。それでもゲームが誤って識別される場合は、`parser.log`、
表示されているソースと ID、ゲームのディレクトリ名を報告に添付してください。

## ウイルス対策ソフトまたは SmartScreen の警告 {#antivirus-or-smartscreen-warning}

パッケージ化されたリリースは、プロジェクト独自の証明書で署名され、その正確な拇印で固定されています。
一般に信頼される機関が発行したものではないため、Windows SmartScreen が警告することがあります。この証明書を
インストールする必要はありません。アップデートをインストールする前に、AW Next は、署名されていること、
署名者が `CN=Shirow` であること、拇印がアプリに固定された 2 つのうちのいずれかと一致すること、
署名後にファイルが変更されていないことを確認します。リリースとともに公開される SHA-512 は、この確認の代わりにはなりません。
両方が同時に差し替えられてしまうためです。任意のエミュレーター DLL がヒューリスティック検出を引き起こすこともあります。
ダウンロードは
[公式のリリースページ](https://github.com/Shirowwww/Achievement-Watcher-Next/releases)からだけにして、
2 つ目の確認として、インストーラーを対応する `latest.yml` の SHA-512 と照らし合わせてください。

システム全体の保護を無効にしないでください。公式のリリースから隔離されたファイルは、誤検出として
ウイルス対策ベンダーに報告してください。

### リリースを自分で確認する {#checking-a-release-yourself}

公開されているインストーラーは、その SHA-256 で VirusTotal で検索できます。

```powershell
Get-FileHash "Achievement.Watcher.Setup.3.12.5.exe" -Algorithm SHA256
```

`https://www.virustotal.com/gui/file/<the hash it prints>` を開きます。ファイルが公開されたものと同じなら、
レポートはすでにあります。現在のリリースでは、それは
[3.12.5 のインストーラー](https://www.virustotal.com/gui/file/364b7ecdc1d039e74066ec924453ba665ff33b36dded965703c3373fa53b58ea)
(`364b7ecdc1d039e74066ec924453ba665ff33b36dded965703c3373fa53b58ea`)です。

結果には、各エンジンの判定が一覧されます。エミュレーターのファイルを同梱したビルドでヒューリスティック検出が数件あるのは、
以下で説明する誤検出です。重要なのは、ハッシュがリリースページで公開されたファイルと
一致していることです。

### エミュレーターのファイルが検出される {#the-emulator-files-are-flagged}

これは実際によく遭遇する検出で、誤検出です。ストアのクライアントが動いていないゲームの実績を記録するには、
代わりのライブラリをその隣に置くことになります：Steam エミュレーター(GBE
Fork)や Ubisoft のローダーです。検出エンジンはまさにそれを監視しているため、ファイルが*何をするか*を検出するのであり、
何を含んでいるかではありません。Windows Defender は、見える範囲のすべてのコピーを一度に隔離します：ゲーム
フォルダー内、AW Next とともにインストールされたもの、そしてそのキャッシュ内です。

**いつ起きるか。** ファイルが書き込まれる瞬間、そのときだけです。

| 行ったこと | 書き込まれるもの |
|---|---|
| ゲームのメニューまたは設定から修復を実行した | エミュレーターまたはローダーを、そのゲームのフォルダーに |
| **設定 → エミュレーター → Ubisoft / Uplay R1/R2** を開いた | 同梱のローダーを、AW Next 自身のキャッシュに |
| **新しく検出されたゲームを自動修正** をオンにした | 同じものを、スキャン中に、必要とする各ゲームに |

AW Next を起動しても、それらは何も書き込まれません。自動修復は、オンにしない限りオフで、事前に警告し、
先に Defender の除外を追加する機会も与えます。すでにオンだった場合は、同じ警告が最初の書き込みの前に一度表示され、
ダイアログに除外とオフにするスイッチが示されます。
ウィンドウがトレイに隠れている間は何も書き込まれません。

**AW Next の対応。** 隔離はウイルス対策の問題として報告され、Windows Defender でフォルダーを許可するボタンと、
削除されたファイルを元に戻すボタンが表示されます。**設定 →
エミュレーター → Ubisoft / Uplay R1/R2 → 内蔵 DLL を復元** は、いつでも復元します。

**対処。** ウイルス対策ソフトが名指ししたファイルを許可するか、
`%APPDATA%\Achievement Watcher Next\cache` を除外してください。これは AW Next 自身のコピーを保護します。ゲームフォルダーにあるコピーは
やはり検出されることがあるので、続くようならそのフォルダーも除外してください。ベンダーに誤検出を報告すれば、
全員の問題が解決します。

Windows Defender は、AW Next が GBE Fork のアーカイブをキャッシュにダウンロードする間、それを
`Trojan:Win32/Suschil!rfn` と呼びます。同じ誤検出です。許可するか、キャッシュフォルダーを除外して、修復をもう一度
実行してください。

**最初に確認すること。** どちらもサードパーティ製のオープンソースです：Steam エミュレーターは公式の
[GSE Fork のリリース](https://github.com/Detanup01/gbe_fork)から、Ubisoft のローダーはリポジトリの
`app/resources/uplayR1/` と `app/resources/uplayR2/` に同梱されています。AW Next は、同梱のものを
既知の SHA-256 ダイジェスト、PE アーキテクチャ、実績の対応能力に照らして、修復で使う前に確認し、
確認に失敗したファイルは拒否します。

### AW Next の実行中にウイルス対策ソフトが反応する {#an-antivirus-reacts-while-aw-next-runs}

振る舞い検知エンジン(Kaspersky の System Watcher、Bitdefender の Advanced Threat Defense)は、プログラムが何を含むかではなく、
何をするかで判断します。AW Next は、Windows 通知、通知サウンド、アップデートの署名チェックのために PowerShell を起動せず、
`%TEMP%` にコードをコンパイルすることもありません。スクリーンショットにはアプリに同梱のネイティブヘルパーを使い、
通知のチェックは Windows を直接呼び出します。

それでもウイルス対策ソフトが反応する場合は、検出名を正確に控えて、名指しされたファイルを誤検出として報告してください。
Kaspersky なら [opentip.kaspersky.com](https://opentip.kaspersky.com) で、ハッシュでファイルを検索し、
**Submit to reanalyze** を押します。

## ウィンドウが開かない {#the-window-does-not-open}

- アプリが非表示で起動した場合に備えて、トレイアイコン(通知領域)を使います。
- 固まった AW Next のプロセスを終了してから、もう一度起動します。
- 開発のために `ELECTRON_RUN_AS_NODE` が設定されていた場合は、環境から取り除いてください。これがあると
  Electron が単なる Node として起動します。
- `renderer.log` とメインのアプリのログで、最初のエラーを確認します。
- UI が変更できるほど長く表示されているなら、**設定 → 一般 → ハードウェアアクセラレーションを無効化** を試します。

## 新しいプロファイルで始める {#start-with-a-fresh-profile}

残したいデータをバックアップしてから、これを行ってください。

1. トレイから AW Next を完全に終了します。
2. `%APPDATA%\Achievement Watcher Next` を `Achievement Watcher Next.backup` に名前変更します。
3. アプリを起動して、新しいプロファイルで問題を再現します。

問題が消えたら、必要なデータだけを復元するか、関連する設定ファイルを報告に添付してください。
名前変更なら元に戻せますが、削除では戻せません。

## 問題を報告する {#report-the-problem}

まず[既存の issue](https://github.com/Shirowwww/Achievement-Watcher-Next/issues)を検索してください。
該当するものがなければ、リポジトリのテンプレートでバグを報告し、公開したくないものを取り除いたログを添付してください。
