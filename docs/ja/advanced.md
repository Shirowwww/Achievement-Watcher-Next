# 詳細ツール

これらのツールは **設定 → 詳細** またはゲームの右クリックメニューにあります。詳細タブは
インターフェースが **詳細** モードのときにだけあります。見当たらない場合は、設定の上部にある **インターフェース** の
コントロールを切り替えてください。元に戻しても何も失われません。

## セットアップとメンテナンス {#setup-and-maintenance}

| ツール | 内容 |
|---|---|
| **検出されたすべてのゲームを修正** | インストールフォルダーが分かっている、対応するすべての検出済みゲームに、該当する修復(Steam/GBE Fork または Ubisoft/Uplay R2)を実行します。すでにセットアップのあるゲームを再構築します。 |
| **ハードウェアアクセラレーションを無効化** | ウィンドウやオーバーレイの動作がおかしいときに、GPU アクセラレーションをオフにします。再起動が必要です。 |
| **キャッシュを消去** | 再ダウンロードできるキャッシュだけを削除します：アップデートのファイル、Steam/Ubisoft のスキーマとアイコンのキャッシュ、ダウンロードしたエミュレーター修正ツール。設定、セーブ、バックアップ、手動で置いたファイルには決して触れません。 |
| **実績リストを再確認** | ゲームのアップデートで追加された実績を Steam に問い合わせます。これは 3 日ごとに実行され、このボタンはそれを今すぐ強制します。 |
| **実績データの自動更新** | 既定でオン。オフにすると、`steam_cache` を手動で管理している人向けに、この再確認と空の説明の修復が止まります。オフの間も **実績リストを再確認** は動作します。 |

ソースごとの修復設定は **設定 → エミュレーター** にあります。**Ubisoft / Uplay R2** には
パッケージの状態、DLL のインポート/復元のコントロール、対象を絞ったバッチ修復があり、ローダーと INI の詳細は
自動のままです。

アップデートが同じダウンロード済みファイルで失敗し続けるときは、まず **キャッシュを消去** を試してください。

## 診断 {#diagnostics}

<div align="center">
<picture><source srcset="../assets/shot/diagnostics-panel-800.webp 800w, ../assets/shot/diagnostics-panel.webp 940w" sizes="(max-width: 700px) 100vw, 720px"><img src="../screenshot/diagnostics-panel.png" width="720" height="529" alt="設定 - 詳細、診断" loading="lazy" decoding="async"></picture><br>
<sub>バージョンと、ログおよびデータフォルダーへのワンクリックのアクセス</sub>
</div>

診断カードには、アプリ、Electron、Node、Chrome のバージョンが表示され、ログのフォルダー、
データのフォルダー、アップデートの確認を開けます。**ログをエクスポート (.zip)** は、アプリの実行中にすべてのログファイルを
1 つのアーカイブにまとめます。ログを書き込むプロセスが止まらないため、手でコピーするのは確実ではありません。
ユーザー名とあらゆるキー、トークン、パスワードはアーカイブ内でマスクされ、ディスク上のログではマスクされません。バグ報告に必要なものは、
[トラブルシューティング](troubleshooting.md#open-logs-and-local-data)を参照してください。

## プロファイルのバックアップ {#profile-backup}

<div align="center">
<picture><source srcset="../assets/shot/profile-backup-panel-800.webp 800w, ../assets/shot/profile-backup-panel.webp 940w" sizes="(max-width: 700px) 100vw, 720px"><img src="../screenshot/profile-backup-panel.png" width="720" height="529" alt="設定 - 詳細、プロファイルのバックアップ" loading="lazy" decoding="async"></picture><br>
<sub>設定 → 詳細 のプロファイルをエクスポートとプロファイルを復元</sub>
</div>

**プロファイルをエクスポート…** は、設定、ライブラリの選択、プリセット、テーマ、カバー、カスタム背景、
GBE の復元ポイント、プレイ時間を 1 つの `.awbackup` ファイルに保存します。再インストールや新しいPCのためのものです。サインイン、
キャッシュ、ログは保存されないため、あとで Epic、Steam、Xbox、PlayStation、
RetroAchievements に再度サインインします。**プロファイルを復元…** はまずファイル全体を検証し、
次の起動時に適用します。置き換えられるファイルは保持され、復元に失敗した場合はすべてが元に戻ります。

## 削除したゲーム {#removed-games}

**AW Next から削除** で取り除いたゲームは **設定 → 一般 → 削除したゲーム** に一覧され、
1 つずつ、またはまとめて戻せます。スキャンが見つけ続けるがゲームではない迷子のフォルダーに使ってください。本物のゲームを
見えなくするだけなら、**表示から隠す** のほうが軽い方法です
([ゲームを隠す、削除する、消去する](#hide-remove-or-clear-a-game)を参照)。

## ゲームの実績をリセットする {#reset-a-games-achievements}

ゲームのページのプレイ時間の隣、または右クリックメニューにある **実績をリセット** は、すべての実績を
ロック状態に戻し、ゲームをもう一度最後までプレイできるようにします。AW Next は、解除されるたびに
新しいものとして通知します。

<div align="center">
<picture><source srcset="../assets/shot/achievements-800.webp 800w, ../assets/shot/achievements.webp 1280w" sizes="(max-width: 700px) 100vw, 800px"><img src="../screenshot/achievements.png" width="800" height="492" alt="実績をリセットのあるゲームのページ" loading="lazy" decoding="async"></picture><br>
<sub>リセットは、ゲーム自身のページの達成数の隣にあります</sub>
</div>

関係するすべてのファイルは、まず
`%APPDATA%\Achievement Watcher Next\backups\achievements\<appid>\<date>\` にバックアップされ、確認画面には何かに触れる前に
正確なファイルが一覧されます。バックアップに失敗したファイルは、消去されずにスキップされます。

| ソース | リセットの内容 |
|---|---|
| Steam エミュレーター(Goldberg / GBE と、Goldberg SocialClub と Uplay R2 を含む互換性のある構成) | 実績のセーブを削除します。エミュレーターは次の解除で新しいものを書き込みます。 |
| RPCS3 | `TROPUSR.DAT` を削除します。トロフィーリスト(`TROPCONF.SFM`)はそのままです。 |
| ShadPS4 | トロフィーリストも保持している `TROP*.XML` の中のトロフィーを再ロックするため、ファイルは削除されず編集されます。 |
| KytyPS5 | ゲームの `trophies_*.json` 解除ファイルを削除します。トロフィーリストはゲーム自身のパッケージに残ります。 |
| Xenia | 実績リストも保持している `.gpd` の中の獲得フラグを消去するため、ファイルは編集されます。 |
| Steam、GOG Galaxy、Ubisoft Connect、EA、Epic、Xbox | **できません。** これらは解除をアカウントに保持して再同期するため、消去できるのはアカウントだけです。AW Next はそのように表示します。 |

実績の隣に保存された進捗カウンター(`stats.ini`、`stats.bin` など)もリセットされ、バックアップされます。
「1000 km 移動する」という実績では、カウンターが進捗そのものであり、満タンのままにすると
実績がすぐに発動するか、二度と発動しなくなるためです。

同じ右クリックメニューの **実績のバックアップを復元** は、リセット全体を元に戻します。そのあと
ライブラリを更新して、復元された解除を読み取ってください。

> [!NOTE]
> リセットは、実行中のバックグラウンドのトラッカーを含め、すでに解除されたものについての AW Next 自身の記録も
> 消去します。そうしないと、獲得し直した実績が二度と通知されなくなってしまいます。

## 1 つの実績だけを再ロックする {#re-lock-a-single-achievement}

ゲームのページで解除済みの実績を右クリックし、**この実績を再ロック** を選ぶと、その 1 つだけを
もう一度プレイできます。ロックに戻るのはその実績だけです：エミュレーターのセーブにあるそのフラグ、解除時刻、
進捗、セーブが結び付けている場合はそのカウンター、そして AW Next 自身の
記録で、獲得し直したときに新しいものとして通知されます。確認画面にはファイルが一覧され、すべてのファイルが
リセットと同様に先にバックアップされます。**実績のバックアップを復元** で元に戻せます。

先にゲームを閉じてください。エミュレーターは解除をメモリに保持し、ゲームの終了時に書き戻すため、
変更が打ち消されてしまいます。そのため、ゲームの実行中は AW Next が拒否します。

対象は、Steam エミュレーター(Goldberg と GSE、CODEX、RUNE、OnlineFix、RLD!、
3DM、ALI213、TENOKE、Hoodlum、RAZOR1911、CreamAPI)、UniverseLAN、Nemirtingas、Uplay R1 と R2、
Windows 上の GreenLuma と LumaPlay のテキストのセーブ、そして RPCS3、ShadPS4、Xenia、KytyPS5、Xbox
360 ポート、XLLN のコンソールのセーブです。SmartSteamEmu(`stats.bin`)と SKIDROW(`achieve.dat`)のセーブは、構造が文書化されていないため、
1 つずつの実績単位では編集されません。それらには **実績をリセット** を使ってください。

## ゲームを隠す、削除する、消去する {#hide-remove-or-clear-a-game}

ゲームの右クリックメニューには、ゲームを見えなくする方法が軽いものから強いものまで 3 つあります。

| 項目 | 動作 | 元に戻す方法 |
|---|---|---|
| **表示から隠す** | ゲームは「すべてのゲーム」、すべてのコレクション、統計から消えますが、追跡と通知は続きます。 | ゲームが隠れている間は、コレクションメニューに **非表示** ビューが表示されます。そこで右クリックして **再表示する** を選びます。 |
| **AW Next から削除** | スキャンがそのゲームをスキップし、ライブラリから消えます。ゲームではないツールなどのためのものです。 | **設定 → 一般 → 削除したゲーム**。 |
| **このゲームのデータを消去...** | AW Next がそのゲームについて保持するすべてが消去されます：実績のセーブ(リセットと同様に先にバックアップされます)、プレイ時間、キャッシュされた実績リストとアイコン、ゲームごとの設定、そして AW Next がそのフォルダーに書き込んだエミュレーターの設定です。確認画面に、まず各部分が一覧されます。 | 元に戻すものはありません：次のスキャンで、そのゲームが新しいものとして再び見つかります。 |

## ゲームの名前を変更する {#renaming-a-game}

右クリックメニューの **ゲーム設定 → 名前を変更…** は、ゲームが表示される名前を設定します：タイルと画面、検索と
並べ替え、通知、スクリーンショットとクリップが保存されるフォルダーに反映されます。
検索では元の名前でもゲームが見つかります。欄を空にするか、
**元の名前に戻す** を選ぶと元に戻ります。名前はゲームごとに `cfg/gameTitles.json` に保持されるため、
再スキャンのあとも残り、プロファイルのバックアップに含まれます。カバーの検索とゲームの照合には元の名前が使われます。

**設定 → 一般 → ゲーム名を自分の言語で表示**(既定でオン)は、Steam のゲームを、実績の言語で
Steam が付けるタイトル(ゲームに独自の言語があればその言語)で表示します。
カバーも同じ言語に従います。Steam のローカルカタログは、Steam クライアントが把握しているゲームに答え、
残りは一度、まとめて問い合わせられ、1 か月後に再確認されます。自分で設定した名前が
常に優先されます。

## ゲームのプレイ時間を編集する {#editing-a-games-playtime}

右クリックメニューの **実績とプレイ時間 → プレイ時間を編集…** は、ゲームの合計プレイ時間を置き換えます。
たとえば別のトラッカーから引き継いだものや、セッションが抜けているものです。時間(`12.5`)、または時間と分(`12h30` または
`12:30`)を入力します。最後のセッションの日付は保持され、AW Next は以降のセッションを新しい合計に
加算します。Steam で所有しているゲームは、Steam が報告するプレイ時間を下回ることはありません。
次のスキャンで、より低い合計は Steam の値に引き上げられます。

## 1 つのゲームだけ実績の言語を変える {#a-different-achievement-language-for-one-game}

右クリックメニューの **ゲーム設定 → 実績の言語** は、1 つのゲームの実績と通知を、ライブラリのほかの部分とは別の言語で
表示します。**アプリと同じ** で全体の設定に戻ります。

## ゲームを手動で追加する {#add-a-game-manually}

ライブラリ検索の隣の `+` は、タイトルと実行ファイルからゲームを追加します。プラットフォームと Steam AppID は任意です。
どのソースにも検出されないゲームに使ってください：単独のビルド、ポータブル版の
インストール、自分で起動するエミュレーターなどです。

手動で追加したゲームは：

- 起動でき、ほかのエントリと同じようにプレイ時間を追跡する。
- 実績がなければ **実績なし** と表示し、0% として数えられる代わりに
  達成率の統計から除外される。
- AppID を追加すれば、作り直さずに、あとから Steam の実績スキーマを取り込める。
- ゲームごとの診断は保護されたまま残り、破壊的な操作は隠れたままになる。

手動で追加したフォルダーには、スマート検索が見つけた場所と区別できるよう、フォルダー一覧に小さなアイコンが付きます。

## ゲームの AppID を手動で設定する {#set-a-games-appid-by-hand}

フォルダー名が複数の Steam リリースに一致して、自動の照合が誤ったものを選んだゲームを右クリックし、
**AppID を手動で設定...** を選びます。この選択はインストールフォルダーごとに記憶され、
`steam_appid.txt` に書き込まれます。**手動の AppID を解除** で元に戻せます。ゲームの状態の
**ゲーム ID ファイルを修正** も、AW Next 自身の提案を出発点として AppID を尋ねます。

## 実績を解除済みとしてマークする {#mark-an-achievement-as-unlocked}

ソースが認識できない実績(追跡を設定する前に獲得したものや、エミュレーターが記録しなかったもの)は、
右クリックメニューの **手動解除としてマーク** でマークできます。**手動解除をクリア** で元に戻せます。手動の解除は
スキャンをまたいで保持され、リセットで消去されます。

## 実績の下のステップ {#steps-under-an-achievement}

長い実績は、自分で書いてチェックできるステップに分けられます。ゲームのページでカーソルを合わせて
**ステップ** を開くか、右クリックして **ステップを追加** を選び、ステップを入力して Enter を押します。
ボックスをクリックしてステップにチェックを入れ、テキストをダブルクリックして名前を変更し、×印で削除します。
ゲームがステップを報告することはないため、実績のバーを埋めるだけです。解除は引き続きゲームから行われ、
解除されるとすべてのステップが完了と表示されます。ゲーム内オーバーレイにも同じステップが表示され、
マウスやコントローラーでチェックできます。

ゲームのヘッダーの **ステップ** は、共有するためにリストをファイルにエクスポートしたり、インポートしたりします。ファイルに含まれるのは
テキストでチェックの状態ではなく、実績は ID、次に名前で照合されます。すでにあるステップは
チェックを保持します。ステップは `cfg/achievement-steps.json` に保存され、プロファイルのバックアップに含まれます。

## エミュレーターと修復ツール {#emulator-and-repair-tools}

Goldberg / GBE Fork のセットアップの診断と修復、GBE ランタイムのインストーラー、Steamless、
任意の API チェックのバイパスは、**設定 → エミュレーター** と各ゲームの
**エミュレーターとツール** サブメニューにあります。それぞれのガイド：

- [Goldberg / GBE のセットアップ](emulator-setup.md) - エミュレートされた Steam ゲームの診断と修復
- [Uplay のセットアップ、R1 と R2](uplay-r2.md) - Ubisoft 向けの同様の手順
- [Goldberg / GBE リファレンス](../goldberg-gbe.md) - ファイル形式と検出ルール

同じメニューの **AW Next のエミュレーター設定を削除** は、AW Next がゲームの `configs.user.ini` に書き込んだ
DLC セクション、スイッチ、識別キーだけを元に戻し、自分やリパックが設定した値には決して触れず、
ほかに何も残っていないときにだけファイルを削除します。削除する内容をまず正確に表示します。
このファイルをバックアップしていなかった場合、元に戻す唯一の方法がこの表示です。

**GOG の実績修正 (UniverseLAN) を適用…** は、Galaxy の dll を同梱する GOG のゲームに表示されます。そのゲームの Galaxy SDK に合った
UniverseLAN のビルドをインストールし、元の dll をバックアップとして保持し、既存の UniverseLAN のセーブを
上書きすることは決してありません。`%LOCALAPPDATA%\UniverseLAN` の下に書き込まれる解除は、
ほかと同じように読み取られ、通知されます。

修復によってサポート対象のエミュレーターに置き換えられた場合、[ゲームの状態](game-health.md#the-repairs)の
**エミュレーターの切り替えを元に戻す** で、クラック版自身のファイルが戻ります。

> [!WARNING]
> 修復はバックアップを作成しますが、それでもゲームのファイルを変更します。自分が所有するゲームにだけ使ってください。
