# 実績の通知とポップアップ

AW Next は、解除をネイティブの Windows 通知(トースト)、ゲーム内オーバーレイのポップアップ、またはその両方で知らせます。
方法は **設定 → 通知** で選びます。

Linux では通知はデスクトップ標準のもの(GNOME または KDE)で、オーバーレイも同じように動作します。
応答不可と優先度の高い通知のスイッチについては、[対応デスクトップ](linux.md#supported-desktops)を参照してください。

## 配信モードを選ぶ {#choose-a-delivery-mode}

| モード | 動作 |
|---|---|
| **自動**(既定) | 表示できるときはゲーム内オーバーレイ、できないときは Windows 通知。 |
| **ゲーム内オーバーレイ** | 常に、実行中のゲームの上にスタイル付きのポップアップを表示します。見えない可能性のある排他的フルスクリーンでも同様です。オーバーレイをまったく表示できない場合、その通知は Windows 通知として届きます。 |
| **Windows 通知** | 常に Windows のシステム通知。実績と進捗の通知には実績のアイコンが使われ、プレイ時間の通知にはゲームのアートワークと進捗バーを含められます。 |
| **両方** | 同じイベントを両方の経路で届けます。 |

AW Next は Windows 通知を自分で投稿し、PowerShell を含むほかのプログラムを起動しないため、通知はすぐに
表示されます。`options.ini`(`[notification_advanced] appID`)に設定したカスタムのアプリ ID は、従来どおり
PowerShell 経由になります。

ライブラリのウィンドウは、どのモードでも閉じたままで構いません。配信はバックグラウンドのトラッカーが担当します。

<sub>選択したプリセットがゲーム自身のアートワークで描画するオーバーレイのポップアップ</sub>
</div>

モードにかかわらず、**Websocket @localhost:8082** はすべての通知イベントを JSON としてローカルの websocket に
配信し、配信用オーバーレイやほかのツールで使えます。既定でオンで、`127.0.0.1` だけで待ち受け、
自分では何も表示しません。使わないならオフにしてください。同じアドレスで、すぐに使える
配信用オーバーレイも提供されます：[配信で解除を表示する(OBS)](#show-unlocks-on-stream-obs)を参照してください。

> [!TIP]
> モードを変えたら、テストボタンを使ってください。テストに成功すれば表示経路は確認できますが、実際の
> 解除がうまくいくかは、ゲームのソースが正しく監視されているかどうかにもよります。

### 自動の判断の仕方 {#how-automatic-decides}

各通知は、そのときに AW Next が観察できる内容から、一度だけ振り分けられます。

| 状況 | 動作 |
|---|---|
| 画面を覆うものがない | ゲーム内オーバーレイ。 |
| ゲームが**フルスクリーン**(Windows のフルスクリーン最適化が効いた Direct3D。ほとんどのゲームが該当) | Windows 通知を、ゲームのフォーカスを奪わずにゲームの上に表示します。優先度の高い通知がオンならそれを、オフなら通常の通知時間のあとに AW Next が閉じるリマインダーを使います。ボーダーレスとウィンドウモードのゲームではオーバーレイのままです。 |
| ゲームが**従来の排他モード**で画面を占有している(古いゲーム、多くの OpenGL ゲーム、またはフルスクリーン最適化がオフ) | ほかのアプリから、その画面には何も描画されません。通知は通知センターに送られ、サウンドとコントローラーの振動は引き続き再生されます。ゲーム側でボーダーレスモードにすると、画面に戻ります。 |
| アプリがポップアップを表示できない(使えるプリセットがない、レンダラーが利用できない) | Windows 通知。 |
| オーバーレイの表示に失敗する | 10 分間は Windows 通知を使い、その後あらためてオーバーレイを試します。 |
| オーバーレイに表示を依頼したが、応答が返ってこない | 重複を避けるため、2 つ目の通知は出しません。次の解除では Windows 通知を使います。 |

AW Next は、ゲームごとに最後に配信に使った経路を記憶し、Windows がゲームが排他的フルスクリーンかどうかを
判断できないときの決め手としてのみ使います。代替の経路を使うのは、はっきり失敗したあとだけなので、
同じ解除が 2 回通知されることはありません。AW Next はゲームに注入せず、
ディスプレイモードの変更も強制しません。

### 現在の状態が表示される場所 {#where-the-current-state-is-shown}

ゲームの **ゲームの状態** パネルには、最後の通知を配信した経路とその理由を示す通知の行があります。たとえば
*動作中 - Windows の代替が有効*(シンプルモード)のようにです。まだ通知がない場合は、設定されたモードが表示されます。ゲームが全画面だった、
または応答不可がオンだったために、Windows が通知を通知センターに残した場合は、その旨が行に表示されます。
[ゲームの状態](game-health.md)を参照してください。

## 優先度の高い Windows 通知 {#priority-windows-notifications}

フルスクリーンのゲームやほかの Windows の自動ルールで **応答不可** がオンになると、通常のトーストは
表示されずに通知センターへ送られます。**設定 → 通知 → 優先度の高い
通知** は、実績の解除を重要なものとして扱います。AW Next がそれらを送ってよいか Windows が一度だけ尋ねます。
答えは Windows の通知設定で変更できます。

既定ではオフで、対象は実績と達成の解除だけです。進捗とプレイ時間は対象外です。
トーストには `urgent` シナリオが使われ、Windows 11(ビルド 22546)以降が必要です。Windows 10 では
この設定は何もしません。[Microsoft のアプリ通知のドキュメント](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/app-notifications-content)を参照してください。

## Steam が起動するゲーム {#games-steam-runs}

Steam は自分が起動するゲームに独自のポップアップを表示するため、AW Next は既定でそれらでは何も出しません。
**設定 → 通知 → Steam クライアントのゲーム** を有効にすると、AW Next の通知も表示され、サウンド、
オーバーレイ、レア度、スクリーンショットの記念が付きます。所有しているゲームと、SteamTools、
LuaTools、GreenLuma 経由で追加したゲームが対象です。AW Next は、Steam が `appcache\stats` に書き換える統計ファイルを追跡します。
AW Next の通知だけにするには、**Steam → 設定 → 通知 → 実績を解除したとき** をオフにしてください。

## ポップアップの見た目 {#how-the-popup-looks}

ゲーム内ポップアップの見た目は**プリセット**で決まります。10 種類がアプリに付属し、自分で作ることもでき、
プリセットは 1 つの `.awpreset` ファイルとして共有できます。[プリセットとプリセットデザイナー](presets.md)を参照してください。
同じ設定の **不透明度**(30% から 100%)で、ポップアップの透け具合を決めます。

## サウンド、音量、表示時間 {#sounds-volume-and-duration}

- 通知の設定から、`.wav`、`.mp3`、`.ogg`、`.flac`、`.m4a`、`.aac` のファイルをインポートできます。
- サウンド一覧の **ランダム** は、通知のたびに、またプレビューやテストのたびに、
  自分のファイルから別のものを再生します。
- **レアな実績のサウンド** と **100%達成のサウンド**(詳細モード)は、オーバーレイと Windows 通知で、それらのポップアップに専用の
  サウンドを設定します。どちらも初期値は「解除と同じ」で、「なし」にするとその種類の
  ポップアップは無音になります。ゲームごとのパネルでそのゲームに選んだサウンドが、引き続き優先されます。
- **進捗のサウンド**(詳細モード)は、進捗のポップアップに同じことをします。サウンドなしに設定したゲームを除き、
  ゲーム自身のサウンドより優先されます。1 つのゲームの進捗ポップアップを無音にするには、そのゲームを右クリックして
  進捗をミュートします。
- **エミュレーター**(詳細モード)は、コンソールごとに専用のプリセットとサウンドを設定します。Xenia、RPCS3、shadPS4、
  Kyty が一覧にあります。再コンパイルされた Xbox 360 ゲームは Xenia の選択に、PS4 ポートは shadPS4 の選択に従い、
  **メインと同じ** はメインの設定を使います。
- オーバーレイの音量は 0% から 200% で、100% を超えるとオーバーレイが音を増幅します。Windows 通知の
  再生は、システムのオーディオ経路に制限されます。
- 表示時間はプリセットに従うか、固定の上限を使います。
- プレイ時間の通知は無音です。

共有されたプリセットは独自のサウンドを持つことがあり、その場合はここで選んだものより優先されます。
[プリセットを共有する](presets.md#share-a-preset)を参照してください。

## 位置とサイズ {#position-and-scale}

通知の設定で、隅、端、中央のいずれかの位置を選びます。位置は画面全体を基準に測られるため、下の基準は
タスクバーの上ではなく下端にあり、プリセットが影や光彩のためにカードの周囲にどれだけ余白を残していても、
カードは選んだ端に接します。AW は
各プリセットを位置ごとに一度、最初のポップアップのあとにバックグラウンドで測定するため、最初のポップアップは
以前の位置に表示されます。カードがテキストの長さに追従するプリセット(PS5 Steam、Slim)は、
ポップアップのたびに測定されるため、約 0.5 秒遅れます。

**位置を変更** はカスタム位置を動かし、残した位置がそのまま使われます。存在しなくなったモニターに保存された位置は、
表示範囲に戻されます。複数の画面では、ポップアップはマウスの下ではなく、プレイ中のゲームの画面に表示され、
カスタム位置はその画面を基準にした位置を保ちます。Windows 通知は常にメイン画面に表示されます。

サイズの設定は、レイアウトを変えずにポップアップ全体の大きさを変え、**位置を変更** はそのサイズで
プレビューします。

### 進捗のポップアップ {#progress-popups}

カウンター型の実績(敵を 50 体倒す、100 km 移動する)は、ステップごとに進捗のポップアップを出せます。
詳細モードでは、**進捗の位置** と **進捗のサイズ** で、それらのポップアップに専用の場所と
大きさを設定できます。既定の **解除と同じ** は、ゲーム自身の位置があればそれに従い、それ以外の
選択はすべてのゲームの進捗ポップアップに適用されます。**進捗の位置** の隣の照準で、進捗専用の
カスタム基準位置を決めます。これらの設定が動かすのは、ゲーム内ポップアップだけです。

共通の通知設定にある **進捗のマイルストーン** は、カウンターが目標の 10、25、50% を新たに超えたときだけ
進捗通知を表示します。ポップアップと Windows 通知に適用されます。解除そのものは常に表示されます。

オーバーレイのリストには専用のキーボードショートカット([オーバーレイのガイド](overlay.md#keyboard-shortcuts-overlay-open)を参照)と、
任意のゲームパッド操作([コントローラーのガイド](controller.md)を参照)があります。

## ゲームごとの動作 {#per-game-behavior}

ゲームのツールパネルを開いて **通知** を選ぶと、そのゲーム専用のポップアップのプリセット、
位置、サウンド、サイズを設定できます。どの項目も全体の設定を引き継ぎ、変更した値だけが
保存されます。サウンドには無音とランダムの選択肢もあります。位置の隣の照準で、そのゲームのポップアップを表示したい場所に
プレビューをドラッグできます。5 つのテストボタンは、実績の進捗を変えずに、そのゲームとアートワークを
プレビューします。削除されたプリセットやサウンドは全体の値に戻り、ユーザープリセットの名前を変更しても
ゲームへの割り当ては維持されます。

ゲームを右クリックすると、解除と達成の通知はそのままで、進捗の通知だけをミュートできます。

全体の解除率がレアの上限以下の実績は、その割合が表示され、プリセットのレア用スタイルが適用されます：5% 以下は
**ゴールド**、10% までは**シルバー**、15% までは**ブロンズ**です。これらの上限は、**設定 → 一般 → レア度のしきい値** を
カスタムにすると動かせます(詳細モード)。

### トロフィーモード {#trophy-mode}

**設定 → 一般 → レア度の表示** で **トロフィーモード** に切り替えると、すべての実績が全体の解除率で
格付けされます(20% 未満はゴールド、50% 未満はシルバー、それ以外または解除率が不明な場合はブロンズ)。ゲームウィンドウ、
オーバーレイ、プロフィールのトロフィー、通知に反映されます。**レア度の
しきい値** で境界を動かせます。3 つのグレードはすべて、プリセットのレア用スタイル(`state-rare` に
`tier-gold`、`tier-silver`、`tier-bronze` を加えたもの)を使い、プラチナは別の達成状態のままです。アプリは
プリセットに `rarityTier`(および `rarityMode` とローカライズされた `rarityGrade`)でそのティアを渡します。
このフィールドのないプリセットは、割合表示に戻ります。

PlayStation アカウントを接続している場合(**設定 → ソース**)、PlayStation でも発売されたゲームは、実績の取得元にかかわらず
本物のトロフィーリストを使います。各実績は、同じ名前または説明を持つトロフィーのグレードと
DLC グループを引き継ぎます。本物のプラチナは、どのレア度モードでも(ゲームのページ、統計、100% のポップアップ)
名前、説明、アイコンとともに表示され、DLC のトロフィーが残っていても、そのトロフィーを獲得した時点で
カウントされます。PlayStation エミュレーターは独自のトロフィーを保持します。AW は
ゲームの元の名前でリストを探すので、ゲームの名前を変えても影響はありません。

リアルタイムのソース(Xenia、再コンパイルされたポート、GOG Galaxy、
Ubisoft Connect、Xbox PC)を含め、すべてのソースが 100% のポップアップを表示します。ゲームにプラチナがある場合、それに結び付いた実績は
プラチナとして表示されます。

## 配信で解除を表示する(OBS) {#show-unlocks-on-stream-obs}

ポップアップをウィンドウとしてキャプチャする方法は使えません。ポップアップのウィンドウは数秒しか存在しないため、
OBS がつかまえられないのです。配信の間ずっと OBS が読み込んだままにする**ブラウザー**ソースを使ってください。

1. **設定 -> 通知 -> OBSブラウザソース。** **プレビュー** は、10 秒ごとにサンプルの解除を表示するページをブラウザーで開き、
   一連の流れが動いていることを確かめるいちばん手早い方法です。**リンクをコピー**
   でアドレスをコピーします。
2. OBS で **+ -> ブラウザー** を選び、アドレスを **URL** に貼り付けます。
3. **幅** と **高さ** を任意に設定します。カードは枠いっぱいに拡大縮小されます。

このソースには、ゲーム内ポップアップと同じプリセット、アートワーク、レア度のスタイルが表示され、設定で選んだ
プリセットに従います。**設定 -> 通知** のテストボタンも、配信モードにかかわらずここに送られます。

> [!TIP]
> **ソースが大きいほど、カードは鮮明になります。** カードはソースのサイズでレイアウトされ、引き伸ばされません。
> プリセット自身の枠の約 2 倍のサイズをソースに設定し、シーンでは半分の大きさで配置してください。
> `http://127.0.0.1:8082/obs/_config` に両方の数値が出ます。ぼやけたままなのは実績のアイコンだけです。
> Steam が 64x64 で公開しているためです。

### オプション {#options}

アドレスの後ろに `?first=x&then=y` の形で付けます。

| オプション | 効果 |
|---|---|
| `?test=1` | ソースの位置合わせのために、10 秒ごとにサンプルの解除を繰り返します。終わったら外してください。 |
| `?scale=2` | ソースに合わせる代わりに、カードをそのズームで固定します。`?scale=app` は設定のサイズに従います。 |
| `?duration=8000` | 設定された表示時間の代わりに、各カードをそのミリ秒数だけ表示します。 |
| `?sound=1` | ブラウザーソース経由で通知サウンドを再生し、デスクトップの音声をキャプチャしなくても配信に届くようにします。アプリがすでにスピーカーで再生しているため、既定ではオフです。ミックスに含めるには、ソースの **OBS で音声を制御する** にチェックを入れます。 |
| `/obs/preset/Xbox/` | デスクトップの設定にかかわらず、配信用に名前を指定した 1 つのプリセットを使います。自作を含め、インストール済みのプリセット名なら何でも使えます。 |

### 注意点 {#notes}

- 解除と解除の間はページが空白なのは仕様です。何も描画されないので、実績が表示されるまで CPU を使いません。
- ローカル専用です。ページとフィードは `127.0.0.1` で待ち受けるため、ネットワーク上のほかの機器からは
  届きません。
- 実績のアイコンは、アートワークをローカルに保持するソース(Goldberg、エミュレーター、自分のライブラリのアート)について、
  このマシンから配信され、通知で告知された画像に限られます。
- そのアドレスを提供するのは AW Next の 1 つのコピー、つまり最初に起動したものです。2 つ目のインスタンスや、
  ポート 8082 を使うほかのものがあると、ソースは接続先を失います。余分なコピーを閉じれば、ソースは数秒以内に
  再接続します。
- 実際の解除でもソースが空白のままなら、テストボタンが動作するかを確認し、次に
  **Websocket** の行がオンかを確認してください。

## Steam のライブラリページの実績 {#achievements-on-steams-library-pages}

Steam は、非 Steam ショートカットのページに実績を表示しません。Steam のプラグイン(デスクトップでは Millennium、
ゲームモードでは Decky)は、同じローカルフィード `ws://127.0.0.1:8082` で、そのショートカットの実績を AW Next に問い合わせ、
自分で描画できます。AW Next は 1 つのゲームずつ応答します。プラグインがゲームを
指定する必要があり、応答にはフォルダー、アカウント、ソース名は含まれません。

リポジトリの `millennium/` フォルダーにある AW Next 専用の Millennium プラグインは、AW Next が認識するすべての
ショートカットに対してこれを行います。ゲームのページに Steam 本来の実績セクション、プレイバーの
カウンター、完全なリスト、Big Picture の「あなたのもの」タブが表示されます。ショートカットが、AW Next のゲームの **実行ファイル** と
同じ exe を起動する場合に、最もよく一致します。その README には、インストール方法、ページが空のままのときに
確認すること、Steam Cartridges、NativeGameLink、Game
Data Linker との併用方法が書かれています。`playnite/` にある Playnite 拡張機能も同じ方法で問い合わせ、Playnite のライブラリにある
あらゆるゲームに対応します。その README には、インストール方法とテーマで配置できるパネルが書かれています。以下のリクエストは、
別のプラグインを書く人向けです。

プラグインは次を送信します。

```json
{ "cmd": "bridge-game", "id": "r1", "exe": "D:\\Games\\Pinyon Shift\\pinyon_shift.exe", "launchOptions": "", "steamAppId": 0, "name": "Forza Horizon" }
```

`cmd` 以外のフィールドは任意で、追加するほど役に立ちます。AW Next は次の順で試します：ライブラリがゲームについて見つけた
exe、起動オプションで指定されたゲームフォルダーまたは ROM(エミュレーターのショートカット)、Steam の AppID、
ゲームフォルダー内のランチャー、exe のファイル名、そして完全一致のタイトル。
ある段階で複数のゲームに一致した場合、AW Next は「見つからない」と応答します。

応答：

```json
{ "cmd": "bridge-game", "id": "r1", "bridge": 1, "found": true,
  "game": { "id": "x360-4D5309C9", "name": "Forza Horizon", "total": 50, "unlocked": 12,
    "achievements": [{ "id": "1", "name": "...", "description": "...", "icon": "https://...", "iconLocked": "https://...",
      "hidden": false, "rarity": 12.5, "unlocked": true, "unlockedAt": 1790000000 }] } }
```

- `unlockedAt` は Unix 秒です。`rarity` と `progress`(一部達成した未解除の実績では `{ "current": 6, "max": 50 }`)は、
  AW Next が把握している場合にだけ含まれます。
- このPCに保存されているアイコンは、`http://127.0.0.1:8082/bridge/icon/...` というアドレスで届きます。
- リストは、最後のスキャンで見たライブラリに、その後に通知された解除を加えたものです。解除は引き続き
  フィードに届きます。ゲームの `id` を `appID` に持つものが届いたら、もう一度問い合わせてページを更新してください。
- プラグインは Steam 自身のページ(`https://steamloopback.host`)かネイティブのプロセスから接続します。
  ウェブサイトからの接続は拒否されます。websocket のパスワードを設定している場合は、同じパスワードが必要です。
- `?client=decky` として接続してはいけません。その名前は、Steam が通知を表示していることを AW Next に伝えるため、
  AW Next が自分のポップアップを出さなくなります。

## スクリーンショットの記念 {#screenshot-souvenirs}

**解除時にスクリーンショット** は、実績が表示された少しあと、ポップアップの表示が終わってから画面の画像を保存するため、
通知も写り込みます。ファイルは
`<folder>\<game>\<achievement> - <date>.png` に保存され、日付はPCのローカル時刻です。同じ行の **フォルダーを開く** で開き、
必要なら先に作成します。フォルダーの既定は `Pictures\Achievement Watcher Next` で、変更できます。

同じ秒に解除された実績はそれぞれ別のファイルになり、Windows がフォルダー名として受け付けないタイトルの
ゲームでも、スクリーンショットは保存されます。マルチモニター環境では、ビデオクリップと同様に、記念のスクリーンショットは
ゲームがあるモニターをキャプチャします。ゲームのウィンドウが見えない場合は、最前面のウィンドウの
モニター、次にプライマリモニターを使います。

### Windows の HDR をオンにしてプレイする {#playing-with-windows-hdr-on}

**HDR スクリーンショット** の既定は **自動** です。キャプチャ時に、AW Next はゲームを表示しているディスプレイで HDR が
有効かどうかを確認します。有効なら、1 回限りのヘルパーが Windows
Graphics Capture で FP16 のフレームをキャプチャし、ハイライトをトーンマップして SDR/sRGB の PNG にしてから終了します。HDR がオフのとき、
**自動** と **オフ** は標準のキャプチャを使います。ヘルパーが失敗した場合(Windows のサポートがない、キャプチャがブロックされた、
タイムアウトなど)も標準のスクリーンショットに切り替わるため、記念のスクリーンショットと
通知は失われません。

## ビデオクリップ {#video-clips}

**解除時のビデオクリップ** は、コンソールのトロフィービデオと同じように動作します。AW Next が追跡しているゲームの実行中は、
直近の数秒間のプレイが、グラフィックスカードのビデオエンコーダーですでに圧縮された状態でメモリに保持されます。
実績が表示されると、その前後の区間が MP4 として
`<folder>\<game>\<achievement> - <date>.mp4` に保存され、その中央にポップアップが入ります。フォルダーは
別の場所を選ばない限り `Videos\Achievement Watcher Next` です。近接して解除された実績は
1 つのクリップを共有します。

| 設定 | 選択肢 | 既定 |
|---|---|---|
| クリップの長さ | 10 ～ 60 秒 | 20 秒 |
| 解除の前 | 0 秒からクリップ全体まで。重いゲームで通知が遅れて届くときに上げます | クリップの半分 |
| 形式 | H.264、HEVC、AV1。MP4 として保存 | H.264 |
| 解像度 | 画面、2160p、1440p、1080p、720p。画面を超えることはありません | 1080p |
| フレームレート | 30 FPS、60 FPS、または画面に追従する無制限(120、144、240 Hz) | 30 FPS |
| 画質 | 低、中、高 | 中 |
| サウンド | ゲームのみ、または PC 全体 | ゲームのみ |

<picture><source srcset="../assets/shot/video-clip-panel-800.webp 800w, ../assets/shot/video-clip-panel.webp 940w" sizes="(max-width: 700px) 100vw, 720px"><img src="../screenshot/video-clip-panel.png" width="720" height="529" alt="設定、通知：オン/オフのスイッチがあるビデオクリップのセクション" loading="lazy" decoding="async"></picture><br>
<sub>ビデオクリップのセクションは通知タブの下部にあり、オンにするまではオフです</sub>
</div>

表の下の行は、お使いの画面での 1 つのクリップのサイズを見積もります。これは上限です。エンコーダーは
固定ビットレートで動作し、静かなシーンではもっと小さくなります。

- **負荷。** ゲームが動いていない間は何も動きません。キャプチャ、スケーリング、エンコードは GPU 上で行われ、ゲームを描画する
  ブロックとは別のエンコーダーブロックを使います。レコーダーが使う CPU は 1 % をかなり下回り、
  メモリは約 70 ～ 110 MB にクリップ 1 つ分です。実績が
  解除されるまで、ディスクには何も書き込まれません。
- **形式。** H.264 は Discord やスマートフォンを含め、どこでも再生できます。HEVC と AV1 はファイルが小さくなります。
  AV1 には GeForce RTX 40、Radeon RX 7000、Intel Arc 以降が必要です。選んだ形式が使えない場合、クリップは
  H.264 で録画されます。ハードウェアの H.264 エンコーダーがないカードは、Windows のソフトウェアエンコーダーを
  プロセッサー上で、最大 1080p、30 FPS で使います。
- **フレームレート。** **無制限** は、ゲームを表示しているモニターのリフレッシュレートで録画し、
  変更にも追従します。エンコーダーがそのレートを拒否した場合、レコーダーは 60、次に 30
  FPS へ下げ、ログに記録します。サイズの見積もりは、無制限では 30 FPS の 2 倍のビットレートを前提とします。
- **レコーダーが応答しなくなったとき。** AW Next は、毎回倍になる待ち時間のあとに再起動し、
  5 回再起動に失敗するとそのゲームを諦めます。書き込みが途中で失敗したクリップは、書き込まれた部分が
  再生できれば残され、そうでなければ削除されます。PC が落ちて書き込みが中途半端になったクリップは、
  次にゲームを録画するときに片付けられます。
- **HDR。** Windows の HDR がオンのとき、クリップは HDR スクリーンショットと同様にトーンマップされます。**HDR スクリーンショット** を
  **オフ** にすると、クリップにも適用されます。
- **サウンド。** **ゲームのみ** はボイスチャットと音楽を除きます。ゲームの音だけを録音できない場合は、
  PC 全体が録音されます。
- **キャプチャされるもの。** ゲームを表示しているモニターで、通知も含みます。排他的フルスクリーンの非常に古いゲームでは、
  黒いフレームが録画されることがあります。

## テストや解除が表示されないとき {#if-a-test-or-unlock-does-not-appear}

1. 通知が有効になっていることを確認し、ゲームの
   **[ゲームの状態](game-health.md)** パネルの通知の行を読みます。
2. バックグラウンドのトラッカーが動作していることを確認します。
3. オーバーレイの場合は、有効なプリセットを選び、排他的フルスクリーンのゲームの外でもう一度テストします。
   **自動** はすでに両方のケースを処理します。
4. フルスクリーンのゲームや応答不可で Windows 通知が隠れる場合は、**優先度の高い
   通知** を有効にして、Windows の一度だけの確認を承認します。
5. AW Next に対する Windows の通知設定を確認します。
6. **設定 → 詳細 → 診断** を開いて、ログを確認します。

問題が解決しない場合は、[トラブルシューティング](troubleshooting.md#notifications-do-not-appear)に進んでください。
